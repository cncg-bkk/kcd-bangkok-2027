## 1. เกี่ยวกับ KCD Bangkok

Kubernetes Community Days (KCD) คืองานสัมมนาที่จัดโดยชุมชน ภายใต้การสนับสนุนของ Cloud Native Computing Foundation (CNCF) เพื่อรวมผู้ใช้งาน ผู้มีส่วนร่วมพัฒนา (contributor) และผู้ที่เพิ่งเริ่มต้นในโลก Cloud Native มาเรียนรู้และแลกเปลี่ยนประสบการณ์ร่วมกัน

KCD Bangkok 2027 เป็นงาน 1 วันสำหรับวิศวกร สถาปนิกระบบ SRE ทีม Platform นักพัฒนา และผู้นำด้านเทคโนโลยีจากทั่วประเทศไทยและเอเชียตะวันออกเฉียงใต้ เป้าหมายของเราคือ **สร้างชุมชน Cloud Native ในประเทศให้เติบโต** แบ่งปันบทเรียนจากการใช้งานจริง และ **เปิดเวทีให้ผู้พูดหน้าใหม่**

เรายินดีต้อนรับวิทยากรทุกระดับประสบการณ์ และ **สนับสนุนให้ผู้ที่ไม่เคยขึ้นพูดมาก่อนสมัครเข้ามาเป็นพิเศษ**

## 3. หัวข้อและ Track

เรามองหา Talk ที่เน้นการใช้งานจริงและประสบการณ์ตรง โดยแบ่งเป็น Track ดังนี้

### 🛠️ Track 1 — Platform Engineering & Developer Experience
- Internal Developer Platform (IDP), golden paths, Backstage
- Multi-tenancy, self-service infrastructure
- GitOps (Argo CD, Flux), progressive delivery

### ☁️ Track 2 — Kubernetes Operations & Infrastructure
- การดูแล lifecycle ของ cluster, การ upgrade, multi-cluster / hybrid / multi-cloud
- Networking (CNI, service mesh, Gateway API, eBPF)
- Storage, stateful workloads, backup & DR
- การลดต้นทุนและ FinOps

### 🔭 Track 3 — Observability & Reliability
- OpenTelemetry, Prometheus, Grafana stack (Loki, Tempo, Mimir)
- แนวปฏิบัติ SRE, SLO, incident response, chaos engineering

### 🔐 Track 4 — Security & Compliance
- Supply chain security (SBOM, Sigstore, SLSA)
- Policy as code (OPA/Gatekeeper, Kyverno), runtime security (Falco)
- การใช้ Cloud Native ในอุตสาหกรรมที่มีการกำกับดูแล (FinTech ธนาคาร ภาครัฐ)

### 🤖 Track 5 — AI/ML & Emerging Workloads บน Kubernetes
- Model serving, GPU scheduling, AI platform engineering
- Data pipeline และ streaming บน Kubernetes
- WebAssembly, edge computing

### 🌱 Track 6 — Community, Culture & Career
- การมีส่วนร่วมในโปรเจกต์ CNCF และเส้นทาง open source
- การสร้างและขยายทีม Platform
- เรื่องราวการนำ Cloud Native มาใช้ในไทยและภูมิภาค SEA

> หัวข้อของคุณไม่อยู่ในรายการ? ส่งมาได้เลย เราพิจารณา Proposal ที่ดีและเกี่ยวข้องทุกหัวข้อ

## 4. รูปแบบ Session

| รูปแบบ | ระยะเวลา | รายละเอียด |
| --- | --- | --- |
| **Talk** | 30 นาที (25 + ถาม-ตอบ 5) | บรรยายเชิงเทคนิคหรือ case study |
| **Lightning Talk** | 5–10 นาที | หนึ่งไอเดีย หนึ่งเดโม หรือหนึ่งบทเรียน เหมาะกับผู้พูดหน้าใหม่ |
| **Workshop** | 60–90 นาที | ลงมือปฏิบัติ ผู้เข้าร่วมนำโน้ตบุ๊กมาเอง *(จำนวนจำกัด)* |
| **Panel** | 40 นาที | ผู้ร่วมเสวนา 3–4 คนและผู้ดำเนินรายการ (กรุณาระบุผู้ร่วมเสวนาที่ยืนยันแล้ว) |

## 5. ระดับผู้ฟัง

กรุณาระบุระดับของ Session เพียงหนึ่งระดับ

- **Beginner:** ผู้ฟังเพิ่งเริ่มต้นในหัวข้อนี้ ไม่ต้องมีพื้นฐาน
- **Intermediate:** ผู้ฟังรู้พื้นฐานแล้ว ต้องการเนื้อหาเชิงปฏิบัติที่ลึกขึ้น
- **Advanced:** เนื้อหาเชิงลึกสำหรับผู้มีประสบการณ์สูง

## 7. สิ่งที่ต้องส่ง

ส่งผ่าน [Sessionize](https://sessionize.com/kcd-bangkok-2027/) โดยมีข้อมูลดังนี้

1. **ชื่อ Session:** ชัดเจนและเจาะจง (ไม่เกินประมาณ 80 ตัวอักษร)
2. **Abstract:** คำอธิบายที่จะแสดงบน Agenda (ไม่เกินประมาณ 1,000 ตัวอักษร)
3. **รายละเอียดสำหรับกรรมการ:** โครงเรื่อง สิ่งที่ผู้ฟังจะได้รับ แผนการเดโม และเหตุผลที่คุณเหมาะกับหัวข้อนี้ (ไม่เปิดเผยต่อสาธารณะ)
4. **Track รูปแบบ ระดับ และภาษา**
5. **ประวัติวิทยากร** (ไม่เกินประมาณ 500 ตัวอักษร) และ **รูปถ่าย**
6. **ประสบการณ์การบรรยายหรือคลิปที่ผ่านมา** *(ไม่บังคับ)*
7. **วิทยากรร่วม** *(ไม่เกิน 2 คนต่อ Session)*

## 8. เกณฑ์การคัดเลือก

Proposal จะได้รับการพิจารณาโดย **คณะกรรมการจากชุมชน** ซึ่งมาจากหลายองค์กร โดยให้คะแนนตามเกณฑ์ต่อไปนี้

| เกณฑ์ | สิ่งที่เรามองหา |
| --- | --- |
| **ความเกี่ยวข้อง** | ตรงกับ Cloud Native / Kubernetes และกลุ่มผู้ฟังของงาน |
| **ความใหม่** | มีมุมมองใหม่ ไม่ซ้ำกับเนื้อหาที่หาได้ทั่วไป |
| **คุณค่าเชิงปฏิบัติ** | บทเรียนจากการใช้งานจริง สิ่งที่นำไปใช้ได้ เดโมที่ทำซ้ำได้ |
| **ความชัดเจน** | Abstract มีโครงสร้างดีและเล่าเรื่องชัดเจน |
| **ความเป็นกลางทางผลิตภัณฑ์** | ให้ความรู้ ไม่ใช่การขายสินค้า |
| **ความหลากหลาย** | เรามุ่งเปิดพื้นที่ให้วิทยากร องค์กร และมุมมองที่หลากหลาย |

## 9. แนวทางสำหรับวิทยากร

- ✅ **เนื้อหาต้องเป็นกลาง (vendor-neutral)** ไม่รับ Session ที่เป็นการขายสินค้า ส่วน Session ของผู้สนับสนุนจะแยกพิจารณาต่างหาก
- ✅ วิทยากรและเนื้อหาทั้งหมดต้องปฏิบัติตาม **[CNCF Code of Conduct](https://github.com/cncf/foundation/blob/main/code-of-conduct.md)**
- ✅ **การบันทึกวิดีโอ:** Session อาจถูกบันทึกและเผยแพร่ หากมีข้อกังวลกรุณาแจ้งทีมงาน
- ✅ **ส่งได้ไม่เกิน 2 Proposal ต่อคน** (แนะนำให้ส่ง Proposal หลักเพียงอันเดียว)
- ✅ **ใช้ AI ช่วยเขียน Proposal ได้** แต่เนื้อหาและประสบการณ์ต้องเป็นของคุณเอง
- ❌ อย่าส่ง Session ที่คุณไม่สามารถมาบรรยายด้วยตนเองในวันงานได้

## 12. เคล็ดลับเขียน Proposal ให้โดดเด่น

1. **เริ่มจากปัญหา:** คุณแก้ปัญหาอะไร
2. **เจาะจง:** "ลดต้นทุน cluster ลง 40% ด้วย Karpenter ได้อย่างไร" ดีกว่า "การลดต้นทุน Kubernetes"
3. **บอกสิ่งที่ผู้ฟังจะได้รับ:** หลังฟังจบ ผู้ฟังจะทำอะไรได้บ้าง
4. **โชว์ ไม่ใช่ขาย:** แชร์สถาปัตยกรรม ตัวเลข ความผิดพลาด และบทเรียน
5. **ตรวจทานก่อนส่ง:** กรรมการสังเกตเห็นเสมอ
